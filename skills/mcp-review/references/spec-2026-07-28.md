# What 2026-07-28 changed, and which finding catches it

Revision 2026-07-28 is the **current** revision (versioning page, read
2026-10-05). Its changelog is against 2025-11-25. Below, each change that
affects a *server*, with what the server must now do and the id that checks it
statically (`lint_server.py`) or live (`probe.py`).

## Major changes

| # | Change | A server must | Static | Live |
|---|---|---|---|---|
| 1 | Protocol sessions and `Mcp-Session-Id` removed (SEP-2567). List endpoints no longer vary per connection | keep cross-call state in explicit, server-minted handles passed as tool arguments | MCP010 | — |
| 2 | Stateless: no `initialize` / `notifications/initialized`. Version and client capabilities in every request's `_meta` (`io.modelcontextprotocol/protocolVersion`, `.../clientCapabilities`); `serverInfo` in each result's `_meta` (SHOULD) (SEP-2575) | read `_meta` per request; reject unsupported versions with `UnsupportedProtocolVersionError` (-32022) | MCP011, MCP014 | PRB010, PRB032 |
| 3 | `server/discover` (MUST): supported versions, capabilities, identity (SEP-2575) | implement it; it is also the stdio era probe | MCP012 | PRB010, PRB011 |
| 4 | HTTP GET stream and `resources/subscribe` replaced by `subscriptions/listen` (SEP-2575) | deliver change notifications only on listen streams | MCP041, MCP071 | PRB051 |
| 5 | `ping`, `logging/setLevel`, `notifications/roots/list_changed` removed; log level per request in `_meta` (SEP-2575) | not emit `notifications/message` for requests without `logLevel` | MCP041 | — |
| 6 | Tasks moved to the `io.modelcontextprotocol/tasks` extension: `tasks/get` polling, `tasks/update`, no `tasks/result` or `tasks/list`; servers may return task handles without per-request opt-in (SEP-2663) | advertise the extension in `server/discover`; return a `CreateTaskResult` — `resultType: "task"`, a value the **extension** defines, not the core (see row 8) — only to clients whose per-request capabilities declare the extension | MCP090 | — |
| 7 | MRTR replaces server-initiated requests (`roots/list`, `sampling/createMessage`, `elicitation/create`): return `InputRequiredResult` with `inputRequests`, client retries with `inputResponses` (SEP-2322) | return input requests instead of sending them | MCP070 | — |
| 8 | `resultType` required on every result; the core values are `complete` (ordinary results) and `input_required` (MRTR interim results) (SEP-2322). Extensions add their own: the tasks extension's `"task"` (row 6) | include it; clients MUST treat its absence (older servers) as `complete` | MCP030 | PRB030 (accepts `task` too) |
| 9 | SSE resumability (`Last-Event-ID`, event ids) removed (SEP-2575) | drop event stores; a broken stream loses the request | MCP042 | — |

## Minor changes that touch servers

| # | Change | Static | Live |
|---|---|---|---|
| 3 | `tools/list` SHOULD be in a deterministic order | MCP062, MCP063 | PRB033 |
| 4 | `Mcp-Method` (all requests) and `Mcp-Name` (`tools/call`, `resources/read`, `prompts/get`) headers required on Streamable HTTP; mismatches rejected with 400 / -32020; `x-mcp-header` mirrors tool params into `Mcp-Param-*` (SEP-2243) | MCP020, MCP021 | PRB020-022 |
| 5 | `ttlMs` and `cacheScope` (`public`/`private`) required on discover, list and read results (`CacheableResult`, SEP-2549) | MCP031, MCP032 | PRB031 |
| 6 | resource not found: -32002 → -32602 | MCP050 | — |
| 10 | `inputSchema`/`outputSchema` may use any JSON Schema 2020-12 keyword | MCP060 | PRB034 |
| 12 | error code policy: -32000..-32019 legacy, -32020..-32099 reserved for the spec; HeaderMismatch -32020, MissingRequiredClientCapability -32021, UnsupportedProtocolVersion -32022 | MCP051, MCP052 | PRB022 |

Authorization changes (`iss` per RFC 9207, client credentials bound to their
issuer, DCR `application_type`) are covered by `/mcp-server:mcp-auth`.

## Deprecated (remain functional; earliest removal: first revision on or after 2027-07-28)

| Feature | Migration | Id |
|---|---|---|
| Roots | pass directories via tool parameters, resource URIs or configuration | MCP040 |
| Sampling | call LLM provider APIs directly | MCP040 |
| Logging | stderr (stdio) or OpenTelemetry | MCP040 |
| HTTP+SSE transport (since 2025-03-26) | Streamable HTTP | MCP082 |
| `includeContext: "thisServer"/"allServers"` | omit or `"none"` | — |
| Dynamic Client Registration | Client ID Metadata Documents | AUT030 |

## What a dual-era server still owes legacy clients

Everything in [spec-2025-11-25.md](spec-2025-11-25.md): `initialize`,
sessions if it mints them, the legacy error codes. The specification lets a
dual-era server serve both concurrently on one endpoint; the v2 SDKs do this.
